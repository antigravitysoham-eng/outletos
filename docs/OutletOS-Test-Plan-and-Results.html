Approach

  • Automated end-to-end suite (server/scripts/e2e.mjs): real HTTP calls against a running instance. It covers authentication, RBAC/ABAC for all nine roles, dashboards, reports and forecasts, POS (including GST, rounding, KOT, discounts, NC, split tender), kitchen display, menu and 86, inventory and purchasing, reservations, finance, connectors (webhook HMAC, ADMS devices, RTSP generation), the ingest API, alerts, AI agents and team management. Test data is created and cleaned up by the suite.
  • Onboarding suite (--onboarding): builds a UAE tenant (AED, VAT 5% inclusive) with varied outlets, tables, team and modules on a fresh workspace. It verifies currency and tax application, module gating, scoped logins and VAT-inclusive billing.
  • Telegram bot (TG01–TG16, part of the main suite): a stand-in for the Telegram Bot API runs inside the test, and updates are posted to the real webhook route. Covers linking, single-use codes, group refusal, role-based command refusal, branch scope, approvals that acknowledge alerts, AI answers and unlinking.
  • Vision parity (npm run test:parity): the JavaScript and Python rule engines produce identical events from the same 43,200 frames.
  • Browser scenarios: walked through in Chrome. A scenario is marked passed only where it was actually executed.

How to run

Main suite (India demo)npm run start:india then node server/scripts/e2e.mjs
Main suite (global demo)npm start then node server/scripts/e2e.mjs http://localhost:8787
Onboarding suiteDelete server/data/outletos-new.db, run npm run start:new, then node server/scripts/e2e.mjs http://localhost:8789 --onboarding
Vision paritynpm run test:parity

Known limitations

  • Accessibility was checked for keyboard use and focus; a full screen-reader (WCAG 2.2 AA) audit has not been done.
  • Vision accuracy targets (≥ 90% precision for real-time alerts) must be validated per site in shadow mode; the demo uses a synthetic detector.
  • Aggregator payout lines are simulated in the demo; real reconciliation needs the platform payout files.
  • No load or soak testing has been done yet: the suite checks correctness, not throughput.
